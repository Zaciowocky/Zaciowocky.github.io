## T1：接线柱连通性判断
### 题目描述

现有 8 个接线柱，编号为 **0～7**，以及 3 根无向导线。第 `i` 根导线连接编号为 `ai` 和 `bi` 的两个接线柱，其中 `i=0,1,2`。

导线的两端允许连接同一个接线柱，此时不改变不同接线柱之间的连通关系。

给定三个导线的端点，以及两个待查询的接线柱编号 `query_u` 和 `query_v`，请使用 Verilog 编写组合逻辑电路，判断这两个接线柱是否连通。

满足以下任一条件时，认为两个接线柱连通：

1. 两个接线柱编号相同。
2. 两个接线柱由一根导线直接连接。
3. 两个接线柱可以通过多根导线构成的路径连接。

端口定义如下，**所有端口名均为小写**：

| 端口名称 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| `a0` | 输入 | `[2:0]` | 第一根导线的一端 |
| `b0` | 输入 | `[2:0]` | 第一根导线的另一端 |
| `a1` | 输入 | `[2:0]` | 第二根导线的一端 |
| `b1` | 输入 | `[2:0]` | 第二根导线的另一端 |
| `a2` | 输入 | `[2:0]` | 第三根导线的一端 |
| `b2` | 输入 | `[2:0]` | 第三根导线的另一端 |
| `query_u` | 输入 | `[2:0]` | 待查询的第一个接线柱 |
| `query_v` | 输入 | `[2:0]` | 待查询的第二个接线柱 |
| `result` | 输出 | 1 位 | 连通时为 `1`，否则为 `0` |


>目前汇总了三种方法：传递闭包（我做的方法），并查集（HINT给出的方法），异或（见[友链：[计组实验] P1 Verilog](https://preskirimasyaro.github.io/posts/%E8%AE%A1%E7%BB%84%E5%AE%9E%E9%AA%8C-p1-verilog/)）。



### 传递闭包

如果进度跟25级一样的话，离散数学2应该刚刚好或者快要学到传递闭包了。（因为前一天晚上在赶离散作业所以我印象深刻）

传递闭包的概念如下：
设 $R$ 是集合 $X$ 上的二元关系。$R$ 的**传递闭包** $R^+$ 是包含 $R$ 的最小传递关系：

<script type="math/tex; mode=display">
R^+=\bigcup_{n=1}^{\infty}R^n
</script>

其中，$R^n$ 表示连续经过 $n$ 次 $R$ 关系所得到的关系。

本题规定接线柱与自身也连通，因此使用**自反传递闭包** $R^*$：

<script type="math/tex; mode=display">
R^*=I\cup R^+
</script>

<script type="math/tex; mode=display">
I=\{(x,x)\mid x\in X\}
</script>

把导线两端的直接连接记为 $R$，则 $(u,v)\in R^*$ 当且仅当接线柱 $u$ 与 $v$ 连通。

在 Verilog 中构造邻接矩阵，并将对角线置为 1，再连续平方两次得到 $M^4$ 即可。本题只有三根导线，任意连通的两个接线柱之间都存在长度不超过 3 的简单路径，因此 $M^4$ 足以表示所有连通关系。


```verilog
module connectivity(
    input  wire [2:0] a0, b0,
    input  wire [2:0] a1, b1,
    input  wire [2:0] a2, b2,
    input  wire [2:0] query_u, query_v,
    output reg       result
);
    reg [63:0] m [0:2];
    integer s, i, j, k;

    always @(*) begin
        m[0] = 64'b0;

        for (i = 0; i < 8; i = i + 1)
            m[0][i*8+i] = 1'b1;

        m[0][{a0, b0}] = 1'b1;
        m[0][{b0, a0}] = 1'b1;
        m[0][{a1, b1}] = 1'b1;
        m[0][{b1, a1}] = 1'b1;
        m[0][{a2, b2}] = 1'b1;
        m[0][{b2, a2}] = 1'b1;

        for (s = 0; s < 2; s = s + 1) begin
            for (i = 0; i < 8; i = i + 1) begin
                for (j = 0; j < 8; j = j + 1) begin
                    m[s+1][i*8+j] = 1'b0;
                    for (k = 0; k < 8; k = k + 1)
                        m[s+1][i*8+j] = m[s+1][i*8+j] |
                            (m[s][i*8+k] & m[s][k*8+j]);
                end
            end
        end

        result = m[2][{query_u, query_v}];
    end
endmodule
```

#### 注意事项
##### 1. 使用布尔矩阵乘法

矩阵元素表示两个接线柱是否连通，取值为 `0` 或 `1`。计算新矩阵时，要检查是否存在中间节点 `k`，使 `i` 到 `k`、`k` 到 `j` 均连通。

因此，矩阵乘法中的“乘法”使用按位与 `&`，“加法”使用按位或 `|`：

    next[i*8+j] = next[i*8+j] |
                  (current[i*8+k] & current[k*8+j]);

只要存在一个满足条件的中间节点，`next[i*8+j]` 就为 `1`。

##### 2. 对角线初始化为 1，导线记录两个方向

每个接线柱都与自身连通，因此邻接矩阵的对角线必须初始化为 `1`：

    m[0][i*8+i] = 1'b1;

对角线为 `1` 也使较短路径的连通关系在后续矩阵平方中得以保留。

导线没有方向，所以连接 `a0` 和 `b0` 时，需要同时设置：

    m[0][{a0, b0}] = 1'b1;
    m[0][{b0, a0}] = 1'b1;

如果导线两端是同一个接线柱，只会再次将对应的对角线元素置为 `1`，不会改变其他连通关系。

##### 3. 每轮计算分别使用旧矩阵和新矩阵

计算一轮矩阵平方时，必须读取旧矩阵，将结果写入另一个矩阵。代码中用 `m[s]` 计算 `m[s+1]`。

不要一边读取、一边覆盖同一个矩阵，否则后续计算可能读到本轮刚更新的元素，计算结果将不再是一次标准的矩阵平方。

连续平方两次的过程为：

    M → M² → M⁴

因此使用 `m[0]`、`m[1]`、`m[2]` 分别保存这三个矩阵。



### 并查集：按组号合并（Quick-Find）

这种解法为每个接线柱维护一个组号 `group_id[i]`。两个接线柱的组号相同，表示它们连通。

#### 初始化

每个接线柱各自属于一个独立的组：

    for (i = 0; i < 8; i = i + 1)
        group_id[i] = i;

#### 合并集合

对于连接 `a[i]` 和 `b[i]` 的导线，先保存 `b[i]` 所属的组号：

    temp = group_id[b[i]];

然后遍历所有接线柱，将属于该组的节点全部改为 `a[i]` 的组号：

    for (j = 0; j < 8; j = j + 1) begin
        if (group_id[j] == temp)
            group_id[j] = group_id[a[i]];
    end

这样，原本属于两个组的所有节点就会具有相同组号，完成集合合并。如果导线两端原本就在同一组，组号不会发生变化。

这里必须先保存 `temp`，不能直接在循环中比较 `group_id[b[i]]`，因为它可能在合并过程中被修改。

#### 查询连通性

处理完三根导线后，比较两个查询节点的组号：

    assign connected =
        (group_id[query_u] == group_id[query_v]);

组号相同则连通，否则不连通。

#### 与父节点形式并查集的区别

Quick-Find 直接保存每个节点的组号：合并时遍历所有节点，查询时直接比较组号。

父节点形式的并查集保存节点的父节点：合并和查询时需要查找根节点。

在本题中，循环描述的是组合逻辑，不需要多个时钟周期。

### 异或（友链）

第三种方法利用异或抵消路径中间节点：将每个接线柱表示为独热码，每根导线表示为两端独热码的异或，枚举三根导线的子集，判断其异或和是否等于两个查询节点独热码的异或。

具体实现和推导见友链：[《[计组实验] P1 Verilog》](https://preskirimasyaro.github.io/posts/%E8%AE%A1%E7%BB%84%E5%AE%9E%E9%AA%8C-p1-verilog/)。

## T2：后按方向优先

### 题目描述

设计一个游戏方向键冲突处理器。玩家通过左、右方向键控制角色水平移动；当两个方向键同时处于按下状态时，按照“最后按下的方向优先”的规则决定移动方向。

模块在每个时钟上升沿采样输入 `left` 和 `right`，并更新输出 `move_left` 和 `move_right`。

### 功能要求

当 `reset = 1'b1` 时，执行高电平有效的**同步复位**：清除保存的历史按键信息，并将 `move_left`、`move_right` 均置为 `1'b0`。复位优先于其他操作。

当 `reset = 1'b0` 时，按照当前按键状态更新输出：

| 当前 `left` | 当前 `right` | 移动方向 | `move_left` | `move_right` |
| :---: | :---: | :--- | :---: | :---: |
| 0 | 0 | 停止 | 0 | 0 |
| 1 | 0 | 向左 | 1 | 0 |
| 0 | 1 | 向右 | 0 | 1 |
| 1 | 1 | 根据历史按键状态决定 | 见下表 | 见下表 |

当当前 `left` 和 `right` 均为 `1'b1` 时，根据上一周期采样到的按键状态决定方向：

| 上一周期 `left` | 上一周期 `right` | 处理规则 |
| :---: | :---: | :--- |
| 0 | 0 | 两个方向键本周期同时按下，规定右方向优先，向右移动 |
| 1 | 0 | 右键是本周期新按下的方向，向右移动 |
| 0 | 1 | 左键是本周期新按下的方向，向左移动 |
| 1 | 1 | 保持上一周期的移动方向 |

任何情况下，`move_left` 和 `move_right` 都不能同时为 `1'b1`。

### 模块规格

模块名：`direction_priority`。

所有端口均为 **1 位**信号。

| 端口名称 | 方向 | 描述 |
| :--- | :---: | :--- |
| `clk` | I | 时钟信号，在上升沿采样输入并更新状态和输出 |
| `reset` | I | 同步复位信号，高电平有效 |
| `left` | I | 左方向键状态，高电平表示按下 |
| `right` | I | 右方向键状态，高电平表示按下 |
| `move_left` | O | 左移信号，高电平表示当前周期向左移动 |
| `move_right` | O | 右移信号，高电平表示当前周期向右移动 |

### 数据范围与保证

- 测试开始时会先进行复位。
- 复位期间，`left` 和 `right` 均为 `1'b0`。
- 每个时钟周期内，`left` 和 `right` 的电平保持稳定。

## T3：简易注释过滤器

### 题目描述

程序中常用 `/* ... */` 表示块注释。请使用 Verilog 实现一个简易注释过滤器，串行接收字符，实时输出自上次复位以来，已读入文本去掉注释后剩余的字符数。

### 过滤规则

`/` 和 `*` 的编码分别为 `8'h2F` 和 `8'h2A`。除这两个值外，所有 8 位输入值均作为普通字符处理，无需检查是否为合法 ASCII。

从左到右处理输入文本，规则如下：

1. 在注释外，连续出现的两个字符 `/*` 表示注释开始。
2. 进入注释后，随后第一次出现的 `*/` 表示注释结束。
3. 不支持嵌套：在注释内不再识别新的开始标记，只查找结束标记。
4. 注释的开始标记、结束标记及内部所有字符均不计入结果。
5. 开始标记和结束标记不能共用字符。例如，`/**/` 是完整注释，而 `/*/` 尚未结束注释。
6. 只识别块注释，不识别 `//` 行注释，也不对引号或转义字符进行特殊处理。

### 实时计数规则

统计结果只根据当前已经读入的字符确定，不等待后续字符：

- 在注释外读到 `/` 时，先将其作为普通字符计数。
- 若紧接着读到 `*`，则确认两者构成开始标记 `/*`。此时扣除此前已计入的 `/`，本次的 `*` 不计数，并进入注释。
- 进入注释后，直到读完结束标记 `*/` 为止，读入的字符均不增加计数。

设从上次复位到最近一次时钟上升沿，已读入文本经过过滤后的字符数为 `N`，则输出 `count` 为 `N` 对 256 取模的结果，即仅保留低 8 位。

例如，累计读入 260 个非注释字符时，输出为 4。

### 模块规格

模块名：`comment_filter`。

**要求使用 Moore 型状态机。** 计数值也是状态的一部分，输出 `count` 仅由当前已寄存的状态决定。

输入 `char` 的变化不会立即改变输出；只有在时钟上升沿采样输入并更新状态后，`count` 才相应更新。

| 端口名称 | 方向 | 位宽 | 描述 |
| :--- | :---: | :---: | :--- |
| `clk` | I | 1 位 | 时钟信号，在上升沿采样输入并更新状态 |
| `reset` | I | 1 位 | 同步复位信号，高电平有效 |
| `char` | I | `[7:0]` | 当前输入字符的编码 |
| `count` | O | `[7:0]` | 过滤后的累计字符数，仅保留低 8 位 |

### 复位与采样规则

每个时钟上升沿按以下优先级处理：

1. 若 `reset = 1'b1`，清空此前的输入记录和内部状态，将 `count` 置为 0，并恢复到注释外状态。本次不接收 `char` 中的字符。
2. 否则，接收 `char` 中的一个字符，按过滤规则更新内部状态和计数值。

保证开始输入前先进行同步复位。
